# v2.0 歌詞意訳レビュー ワークフロー

> **重要**: このワークフローの各ステップは**スキップ禁止**。
> 各ステップ完了の証拠を作業チェックリストに記録すること。

## 処理単位
- **1回の作業で最大3曲**まで
- 3曲終わったら必ずユーザーに報告して次の指示を待つ

---

## Step 1: 背景調査（スキップ禁止）
// turbo
1. `search_web` で「Taylor Swift "[曲名]" 和訳 歌詞 日本語訳」を検索
2. 検索結果から **最低1つの参考訳URL** を取得
3. `read_url_content` で参考訳の内容を取得（または検索結果の要約で確認）
4. **チェックリストに参考URLを記録**

## Step 2: 現状の全行チェック（スキップ禁止）
1. `view_file` で対象HTMLの歌詞部分を全行表示
2. 英語原文（lyric-en）と日本語訳（lyric-ja）を**1行ずつ照合**
3. 以下の問題を特定・分類:
   - **A: 壊滅的MT** — 単語羅列、意味不明
   - **B: 意味の取り違え** — 原文と違う意味
   - **C: 敬体残り** — です/ます/ください
   - **D: 改善可能** — 意味は合ってるがより自然にできる
4. **ステップ1の参考訳と比較**して、現状の訳の品質を評価

## Step 3: 修正適用（スキップ禁止）
1. 問題箇所を `multi_replace_file_content` で修正
2. 修正の根拠を参考訳との比較で説明できること
3. 修正しなかった行も「問題なし」と判断した理由が説明できること

## Step 4: チェックリスト記録（スキップ禁止）
1. 作業チェックリストファイル（`v2-checklist.md`）に記録:
   ```
   ## [曲名]
   - [x] Step1: 背景調査完了 — 参考URL: [URL]
   - [x] Step2: 全行照合完了 — 問題箇所: X件（A:X B:X C:X D:X）
   - [x] Step3: 修正適用 — 修正: X行 / 修正不要: X行
   - [x] Step4: チェックリスト記録
   ```

## Step 5: コミット（3曲まとめて）
// turbo
1. `git add [修正ファイル]`
2. `git commit -m "v2.0: [曲名1]/[曲名2]/[曲名3] 参考訳照合済"`
3. `git push`

---

## 禁止事項
- ❌ grepスキャンだけで修正完了としない
- ❌ 参考サイトを見ずに修正しない
- ❌ チェックリストを記録せずにcommitしない
- ❌ 1回の作業で4曲以上処理しない
